# Local inference operations

## Safe prerequisites

Checkpoint 2.4 expects an already running local Ollama server and an already installed configured
model. It never calls pull, create, copy, push, or delete APIs. Operators verify inventory manually:

```powershell
ollama --version
ollama list
Invoke-RestMethod http://127.0.0.1:11434/api/version
Invoke-RestMethod http://127.0.0.1:11434/api/tags
```

Select the provider in the service-local `.env` only after confirming the model exists:

```dotenv
AI_SERVICE_LLM_PROVIDER=ollama
AI_SERVICE_OLLAMA_BASE_URL=http://127.0.0.1:11434
AI_SERVICE_OLLAMA_MODEL=qwen3.5:35b
AI_SERVICE_OLLAMA_NETWORK_POLICY=loopback
```

Do not expose port 11434 publicly. Do not add cloud model names or authenticate the local client to
Ollama Cloud; the adapter accepts HTTP loopback/private IP origins only and sends no authorization.

## Readiness semantics

`/health` confirms only the FastAPI process. `/ready` uses a cached bounded probe and reports:

- `configuration`: service configuration passed validation;
- `ollama`: `/api/version` and API access are available;
- `model`: the exact configured identifier is listed and `/api/show` succeeds;
- `inference`: model details advertise the completion capability understood by this adapter.

The inference field means configuration/contract compatibility, not that a prompt was generated by
the readiness call. GPU allocation, model loading, and text generation never occur during readiness.

## Integration test execution

Live tests are opt-in and never pull a model:

```powershell
$env:AI_SERVICE_RUN_OLLAMA_INTEGRATION='1'
Set-Location apps/ai-service
..\..\.venv\Scripts\python.exe -m pytest tests/integration/test_ollama_live.py -v -s
```

The suite checks version connectivity, inventory/details, invalid-model and unavailable-service
normalization, bounded Vietnamese/English completions, thinking, usage, real NDJSON streaming and
time to first token, timeout, cancellation, and gateway concurrency one. Model-dependent tests skip
with an explicit reason when inventory lacks the configured model.

## Verified local state on 2026-11-25

Ollama `0.40.16` answered on `127.0.0.1:11434`. `ollama list`, `/api/tags`, and `/api/show` confirmed
`qwen3.5:35b`, digest prefix `c2ee66a3c0d6`, 22 GB, architecture `qwen35moe`, 34.7B parameters,
Q4_K_M, maximum context 262144, and completion/thinking support. The accepted live suite produced
9/9 PASS, including real bounded Vietnamese/English inference and NDJSON streaming. No model was
downloaded, deleted, or modified by the acceptance run.

On the accepted host, cold model load plus completion took 176.8538 seconds. Once warm, bounded
completions took 0.4864 seconds with thinking disabled and 5.4298 seconds with thinking enabled;
streaming TTFT was 0.1172 seconds. These are local observations, not capacity guarantees. Full
evidence and resource samples are recorded in `docs/checkpoints/checkpoint-2.4.md`.

## Checkpoint 2.5 transport policy

Chat transport does not change readiness or load the model at startup. The accepted configuration
uses one active inference, one pending request, a 30-second admission timeout, a 240-second first
content timeout, a 30-second in-stream inactivity timeout, and a 300-second total deadline. The
Ollama read timeout is 300 seconds. These values accommodate the observed cold load but remain
bounded.

The browser never calls this service or Ollama directly. Local verification begins at the Next.js
same-origin route and passes through NestJS. Server origins are configured only with `API_BASE_URL`
and `AI_SERVICE_BASE_URL`; neither is public browser configuration.
